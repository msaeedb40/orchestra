# Security & Isolation Model

Orchestra is designed for multi-cluster environments with security boundaries separating host processes from nested Kubernetes node containers.

## 1. Linux Capability Restrictions
- **Allowed Node Capabilities**: `CAP_NET_ADMIN`, `CAP_SYS_ADMIN`, `CAP_SYS_RESOURCE`, `CAP_IPC_LOCK`, `CAP_SYS_PTRACE`, `CAP_SYS_CHROOT`, `CAP_MKNOD`, `CAP_SETUID`, `CAP_SETGID`, `CAP_DAC_OVERRIDE`.
- **Explicitly Forbidden Capabilities**: `CAP_SYS_BOOT` (preventing guest containers from rebooting the physical host), `CAP_SYS_RAWIO` (preventing direct disk sector and port writes).

## 2. Seccomp-BPF Profile
- All container nodes run with a custom Seccomp profile generated by `orchestra-security::seccomp`.
- Default action: `SCMP_ACT_ERRNO`.
- Permits systemd, containerd, kubelet, and eBPF syscalls (`bpf`, `clone`, `clone3`, `mount`, `pivot_root`, `setns`, `unshare`, etc.).
- Hard blocks host shutdown/damage syscalls (`reboot`, `kexec_load`, `kexec_file_load`, `swapon`, `swapoff`, `lookup_dcookie`, `sysfs`).

## 3. Cgroups v2 & Namespace Boundaries
- Verifies unified cgroup hierarchy (`/sys/fs/cgroup/cgroup.controllers`).
- Requires root controllers for CPU, memory, IO, and PID isolation.
- Audits `/proc/self/ns` across all 7 Linux namespace boundaries (`mnt`, `uts`, `ipc`, `net`, `pid`, `user`, `cgroup`).

## 4. RBAC & Audit Logging
- Role-Based Access Control on gRPC operations (`Admin`, `Operator`, `Viewer`, `NodeAgent`).
- Socket access verification on `/var/run/orchestra.sock` preventing world-writable file permissions.
- Structured audit event stream (`AuditEvent`) logging actor, action, resource, timestamp, and metadata into a ring buffer and persistent JSONL file.
